Hermes Agent API Reference

Hermes is a self-hosted AI agent framework with tool-calling, multi-provider LLM support, and persistent memory. Deploy it behind your firewall and give your team an AI agent that works with your internal tools and data.

Base URL: {server}/api/v1
Auth: API key header
Format: JSON + SSE streaming
Providers: OpenAI, Anthropic, Ollama, Gemini

Overview

Hermes Agent exposes a session-based chat API. Each conversation lives in a Session, and each Session belongs to an Agent with its own system prompt, tools, and LLM provider. The API supports both regular JSON responses and Server-Sent Events (SSE) for streaming.

Core Concepts

Agents
Configured AI personas with system prompts, tools, and LLM settings.
Sessions
Conversational threads. Each has a history and context window.
Messages
User and assistant turns in a session, with optional file attachments.

Authentication

All API endpoints require an API key passed in the X-API-Key header. Generate keys from the Hermes dashboard at Settings → API Keys.

X-API-Key: hms_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
http
POST /api/v1/sessions/sess_abc123/messages
X-API-Key: hms_live_xxxxxxxxxxxxxxxxxxxx
Content-Type: application/json

Tool System

Agents can use tools defined in the OpenAI function-calling format. Tools are registered at the agent level and the model decides when to call them.

json
{
  "name": "search_docs",
  "description": "Search the internal documentation for a query",
  "parameters": {
    "type": "object",
    "properties": {
      "query": { "type": "string", "description": "Search query" },
      "top_k": { "type": "integer", "description": "Max results to return" }
    },
    "required": ["query"]
  }
}

Agents

Agents are the core configuration unit. Each has a name, system prompt, provider config, and a list of tools.

POST /agents

Create a new agent with the specified configuration.

FieldTypeReqDescription
namestringyesDisplay name for the agent.
system_promptstringyesSystem prompt that defines the agent's behavior.
providerenumyesLLM provider: openai, anthropic, ollama, google
modelstringnoModel ID (defaults to provider's recommended model).
temperaturefloatnoSampling temperature 0.0–2.0 (default 0.7).
max_tokensintnoMax response tokens (default 4096).
toolsobject[]noArray of tool definitions (OpenAI function schema).
tools_enabledbooleannoEnable tool calling (default true).
memory_enabledbooleannoEnable persistent memory for this agent (default false).
bash
POST /api/v1/agents
X-API-Key: hms_live_xxxx
Content-Type: application/json

{
  "name": "DevOps Assistant",
  "system_prompt": "You are a senior DevOps engineer. Help with CI/CD, infrastructure, and monitoring.",
  "provider": "anthropic",
  "model": "claude-3-5-sonnet",
  "temperature": 0.5,
  "tools": [
    { "name": "run_command", "description": "Run a shell command on the target host", "parameters": { "type": "object", "properties": { "command": { "type": "string" } } } }
  ]
}

Messages

Send a message to an agent within a session. The agent processes the message and returns a response. For streaming responses, use the SSE endpoint.

POST /sessions/{session_id}/messages

Send a user message and receive a complete assistant response. Use stream=true for SSE streaming.

FieldTypeReqDescription
contentstringyesThe user's message text.
attachmentsobject[]noFile attachments to include in the message.
modelstringnoOverride the agent's default model for this turn.
streambooleannoReturn an SSE stream instead of a full response (default false).
context_windowintnoNumber of recent messages to include in context (default all).
bash
POST /api/v1/sessions/sess_abc123/messages
X-API-Key: hms_live_xxxx
Content-Type: application/json

{
  "content": "What's the status of the production deployment?",
  "attachments": [
    { "file_id": "file_xyz789" }
  ]
}
json
{
  "message": {
    "id": "msg_456",
    "role": "assistant",
    "content": "The production deployment is complete. All 12 pods are running healthy with zero restarts in the last 2 hours.",
    "model": "claude-3-5-sonnet",
    "usage": { "input_tokens": 1240, "output_tokens": 89 },
    "tool_calls": null,
    "created_at": "2025-05-30T14:22:01Z"
  }
}
POST /sessions/{session_id}/messages/stream

Stream the assistant's response token-by-token via Server-Sent Events.

bash
POST /api/v1/sessions/sess_abc123/messages/stream
X-API-Key: hms_live_xxxx
Content-Type: application/json
Accept: text/event-stream

{ "content": "Deploy the latest version to staging" }
sse
event: token
data: "Deploying"

event: token
data: " to"

event: tool_call
data: "{\"tool\":\"run_command\",\"input\":{\"command\":\"kubectl rollout status deployment/web -n staging\"}}"

event: tool_result
data: "deployment web successfully rolled out"

event: done
data: "{\"usage\":{\"input_tokens\":840,\"output_tokens\":312}}"
