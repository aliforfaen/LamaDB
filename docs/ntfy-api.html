NTFY API Reference

NTFY is a simple pub-sub notification service. Send push notifications to your phone or desktop via HTTP requests. No signup, no server required — or self-host it on your own infrastructure.

Base URL: ntfy.sh
Auth: Optional token auth
Format: Plaintext / JSON
Latency: <200ms

Overview

NTFY (pronounced "notify") uses a topic-based publish/subscribe model. Messages are sent to a topic, and all subscribers to that topic receive the message instantly via WebSocket, SSE, or polling.

Key Concepts

Topics
Arbitrarily named channels. Create by publishing to them — no setup required.
Messages
UTF-8 text up to 4096 bytes. Can include tags, priority, and click actions.
Subscribers
Users or apps that receive notifications from topics they're subscribed to.

Authentication

NTFY supports optional token-based authentication to protect topics from unauthorized access. Self-hosted instances can enforce required auth.

http
GET /mytopic
Authorization: Bearer tk_xxxxxxxxxxxxxxxxxxxx

To require authentication on a topic, set an access token in the topic settings or via the API.

Sending Messages

The simplest way to send a notification — just an HTTP GET request. The message body becomes the notification text.

GET /{topic}

Publish a message to a topic via GET. The topic is created automatically if it doesn't exist. If the topic is protected, include the auth token.

ParameterInTypeDescription
topicpathstringTopic name (2-64 chars, lowercase a-z, 0-9, _, -)
X-TitleheaderstringNotification title (defaults to topic name)
X-MessageheaderstringNotification body text
X-PriorityheaderintPriority 1-5 (1=min, 3=default, 5=max)
X-TagsheaderstringComma-separated emoji tags (e.g., "warning,fire")
X-ClickheaderstringURL to open when notification is tapped
X-IconheaderstringURL to an icon to display
X-DelayheaderstringISO 8601 datetime or "+15m" relative delay
X-EmailheaderstringEmail address for email notifications
X-Firebaseheaderstring"yes" to forward to Firebase Cloud Messaging
bash
# Basic notification
curl ntfy.sh/mytopic/mytopic -d "Server backup completed successfully"

# With title, priority, and tags
curl ntfy.sh/mytopic \
  -H "X-Title: Backup Report" \
  -H "X-Priority: 4" \
  -H "X-Tags: white_check_mark,server" \
  -d "Production DB backup finished. Size: 2.3GB in 4m 22s"

# Delayed message (send after 15 minutes)
curl ntfy.sh/mytopic -H "X-Delay: +15m" -d "Reminder: deploy window closes in 1 hour"
POST /{topic}

POST to a topic for full control. The message body can be larger and supports JSON for structured metadata.

FieldTypeDescription
topicstringTopic name (can be passed in URL or JSON body)
messagestringNotification body text (required)
titlestringNotification title
priorityintPriority 1-5
tagsstring[]Array of emoji tag names
clickstringURL to open on tap
attachstringURL to an attachment (shown in notification)
filenamestringAttachment filename
iconstringIcon URL
delaystringISO 8601 datetime or relative (+1h, +30m)
emailstringEmail address for email bridge
actionsobject[]Interactive notification buttons
bash
POST https://ntfy.sh/mytopic
Content-Type: application/json

{
  "topic": "mytopic",
  "message": "Disk space running low on web-01",
  "title": "⚠️ Server Alert",
  "priority": 4,
  "tags": ["warning", "warning"],
  "click": "https://grafana.example.com/d/disk",
  "actions": [
    { "action": "view", "label": "View Dashboard", "url": "https://grafana.example.com" },
    "action": "http", "label": "Acknowledge", "url": "https://api.example.com/ack", "method": "POST" }
  ]
}

Scheduled Messages

Messages can be scheduled for future delivery using the X-Delay header or the delay field in JSON. Relative formats like "+1h" and absolute ISO 8601 timestamps are both supported.

bash
# Relative delays
curl ntfy.sh/reminder -H "X-Delay: +2h30m" -d "Time to check on the build"

# Absolute timestamp
curl ntfy.sh/scheduled -H "X-Delay: 2025-06-15T09:00:00Z" -d "Daily report is ready"

# List pending scheduled messages
curl ntfy.sh/mytopic/json?poll=1

Topic Management

Topics are created on-demand. For persistent topics with access control, you can manage them via the API.

GET /{topic}/stats

Get statistics for a topic — message count, last activity, subscriber count.

json
{
  "topic": "mytopic",
  "subscribers": 3,
  "messages": 1247,
  "last_message": "2025-05-30T14:22:00Z",
  "owner": "tk_xxxxx"
}
POST /{topic} multipart/form-data

Upload a file attachment to a topic. Files are temporarily stored and served as notification attachments.

bash
POST https://ntfy.sh/mytopic
Content-Type: multipart/form-data

file=@error.log
message="New error detected in production"
filename="error.log"
Content-Type="text/plain"

Rate Limits

The public ntfy.sh instance has rate limits to prevent abuse. Self-hosted instances can configure their own limits.

60
requests/minute per IP (anonymous)
300
requests/minute (authenticated)
4KB
max message size

Self-Hosted Setup

Run your own NTFY server with Docker, Kubernetes, or from source. Full control over authentication, storage, and rate limits.

yaml
# docker-compose.yml
services:
  ntfy:
    image: binwiederhier/ntfy
    command: ["serve", "--config-file", "/etc/ntfy/server.yml"]
    ports:
      - "80:80"
    volumes:
      - ./server.yml:/etc/ntfy/server.yml
      - ./cache:/var/cache/ntfy
      - ./data:/var/lib/ntfy
    environment:
      - NTFY_AUTH_FILE: /var/lib/ntfy/user.db
      NTFY_BASICAUTH_FILE: /var/lib/ntfy/auth.db
